# Offline Engine Overlay Preparation

**BLOCKED, software-only.** This prepares an isolated experiment input, not a
deployable model profile. It never pulls images, builds, launches containers,
imports vLLM, installs packages, resolves dependencies, reads weights or contacts
an endpoint. No ABI, GPU, attestation, confidentiality or hardware success is
claimed. The [candidate](p0-t4-cc-candidate.md) remains `BLOCKED`,
`deployable:false`, `image:null`; all five existing patches are unchanged.

The separate [exact-image packaging contract](p0-t4-engine-packaging-contract.md)
is available to explicit offline API calls only. It does not relax this CLI or
recipe, remove root/startup blockers, or authorize image/engine execution.

## Prepare From Committed Source

Use an existing private, non-symlink parent and a new absolute destination:

```sh
python3 -I scripts/prepare-engine-overlay.py --output /private/tmp/nib-engine-context
python3 -I -m unittest discover -s scripts -p 'test_engine*.py'
```

On Linux, select an appropriate absolute private parent instead of the macOS
example. Preparation reads raw committed Git blobs, not working/ignored files,
Git replacements, checkout filters, remote objects or Python bytecode. The two
local helper sources are bounded to 2 MiB, opened nonblocking without following
links, checked as unchanged single-link regular files, then hash-checked before
direct compilation and checked against the same commit. FIFOs, devices,
directories, hard links, symlinks and oversized sources fail with fixed messages.
The preparer and candidate checker's own source rereads are also bounded; the
interpreter's initial script load remains the trusted local bootstrap.
Changing it or a helper requires a commit; do not run concurrently with writers.
The candidate checker's existing application logic supplies all five verified
stages; no second patch engine or package installer is introduced.

Output is an exclusive 0700 directory with 0600 files. It contains a bounded
payload, a fixed-base Dockerfile, a **non-executable partial launch plan**, and
`receipt.json`. Existing output, including a failed attempt, is never reused or
overwritten. Failed writes may leave a partial directory; discard it rather than
infer success from files. Require successful process exit and the complete
receipt. Receipts contain hashes, counts and fixed classifications, not local
paths, environment values, prompts, completions or raw exceptions.

The receipt binds source commit, candidate bundle, combined source bundle,
payload and context. `context_sha256` covers every generated file except the
receipt itself, using the checker's sorted path/length/content digest. The
Dockerfile embeds the payload digest. No build command is provided or executed.
The recipe's default entrypoint fails deliberately, even if someone later builds
it. It does not inherit the upstream serving entrypoint.

## Installed Wheel Gate

The prepared inspector requires Python `-I -S`, Linux/x86_64 and Python 3.12. It
derives installation roots and the console-script directory from the interpreter,
not guessed `site-packages` paths. Every other discovered package root must be
absent or completely empty, even if it contains only an empty directory or a
non-imported file. This conservatively rejects dependency/import precedence
ambiguity instead of checking a partial inventory across roots.
It rejects ambiguous roots, shadow packages,
symlinks, hard links, special files, editable installations and startup `.pth`
hooks. Filename-only startup checks cover both the selected wheel root and every
other existing package root returned by `sysconfig`/`site.getsitepackages()`.
They reject `.pth`/editable path hooks and global `sitecustomize`/`usercustomize`
module names, including source, legacy/cache bytecode and package directories,
without importing or executing hooks. Unknown hooks have no allowlist.
The inspector never imports the installed engine or executes site hooks.
This is a package-root gate, not generic interpreter/stdlib hardening or proof
about arbitrary future `sys.path`, user-site, environment or working-directory
additions. A later launcher still must seal those inputs; no launcher exists here.

Every vLLM RECORD entry must be unique, bounded and accounted for. Source/data
entries require SHA-256 and exact size; only RECORD itself and generated bytecode
may omit hashes. The sole supported outside-root entry is `vllm` in the
interpreter-derived scripts directory, with the pinned console entrypoint. No
other RECORD traversal is followed. Wheel metadata, generated version, platform,
Python constraint and the twelve candidate base sources must agree; the new
helper and its bytecode must be absent. Every patched module also rejects
same-name package directories, native modules and other sibling suffixes before
any write, even with consistent RECORD metadata. Existing source modules may
have legacy/cache bytecode only because application removes it before patching;
the new helper has no such exception. Collision checks repeat after each stage.
Unsupported layouts fail closed.

The dependency check covers the exact pins from the pinned CUDA requirements,
plus the image's declared NCCL build override. It **does not validate every
transitive dependency or open-ended requirement**. There is no invented complete
dependency lock. Package versions, ELF64/x86_64 headers and unchanged native file
inventories are consistency checks, **not ABI compatibility or image-origin
proof**. A malicious self-consistent tree/RECORD is not authenticated by this
inspector. The future build must independently enforce the exact official base
digest and prepared context digest; receipts explicitly say origin is unproven.

Inspection is capped at 100,000 filesystem entries, 32 levels, 32 GiB total,
4 GiB per streamed file, 2 MiB per parsed file and a 300-second filesystem deadline.
The prepared payload is limited to 8 MiB. These are tool safety limits, not claims
about installed image size or startup performance.

Application rechecks the complete inspected inventory before writing. It removes
changed-module legacy and `__pycache__` bytecode, then writes and verifies every
stage. Each stage must leave all other bytes/modes, including native libraries,
unchanged. It preserves the original RECORD rather than misrepresent the result
as an unmodified upstream wheel; the sanitized application receipt is printed.
Any error invalidates the partially modified image. Do not resume it or run it.

## Launch Plan Boundaries

The partial plan seals TP4/DP1, EP off, custom all-reduce off, all four guarded
collective controls off, GEMM-RS off, Engram CPU offload false, and both weight
offload mechanisms at zero. KV offloading/transfer configurations stay absent;
zero is not substituted for the documented unset state. It disables plugins,
telemetry, request/output/access logs, and explicitly disables AllReduce RMS
fusion. The software copy-path override is not hardware detection or attestation.

It is intentionally **not a runnable command**: no model mount, device selection,
startup/output/context limits, runtime budget or executor is supplied. A later
reviewed harness must enforce these, use only synthetic requests inside the
same network-none container, bind the engine to loopback, publish no ports,
discard raw engine output, and confirm cleanup. Native loading, JIT cache needs,
ordinary NCCL, DS-specific execution, memory fit and all hardware gates remain
unqualified. Nothing here changes the existing model pack's DP2 proposal.
